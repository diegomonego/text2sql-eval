v1 results: generating and judging questions for a Text-to-SQL evaluation

Three budgets (N = 5, 10, 15) on TPC-H, each generated once and judged by both independent judges.

What the runs show

  1. Coverage rises with the budget, with diminishing returns. The coverage score goes from 65.98 (N=5) to 77.05 (N=10) to 83.06 (N=15). Every run covers all 8 tables. Shapes reach 8 of 8 from N=10. Columns are the slow dimension: 14, 19 and 30 of 61.
  2. The N=5 trade-off is visible. With five slots, selection favoured dense questions: four of the five need three or more tables, and the first one touches six. It dropped the two lowest-weight shapes, simple lookup (W 0.60) and anti-join (W 0.73), to cover a ratio, a ranking, a time trend and an above-average comparison instead.
  3. Extra slots buy less and less. The generator's gain at the moment of picking falls from about 0.35 for each run's first pick to 0.02 for the 15th. The coverage judge, working independently, agrees: 0 questions at N=5, 2 at N=10 and 5 at N=15 add nothing unique. There are no duplicate pairs.
  4. Every generator label was confirmed by both judges. All 243 labels (tables, columns and shapes) were confirmed by each judge's own links, and none was contradicted. The judges found 5 extra items the generator hadn't labeled.
  5. Correctness is 1.00 at every budget, and that is expected rather than reassuring. The generator drops any candidate whose links fail the code checks, so the questions that reach the judges are answerable by construction. These runs show that the correctness judge agrees with the generator. They don't yet show that it catches bad questions; that is what the controlled check (planned next) tests.

Generation pool, cost and runtime

Each run generated a fresh pool (targeted = max(2N, 16), plus N free slots). Code checked every candidate, removed duplicates and selected exactly N. Costs and durations come from each claude -p run's own log.

Smoke runs

N = 3 runs used to test the skills end to end, including a generator run with no docs and the time anchor off. The no-docs run used no coded columns and no relative dates, and it spelled metrics out instead of relying on glossary terms.

Caveats

  • One run per budget. LLM output varies between runs, so these numbers describe these specific question sets, not the generator's average behaviour.
  • Same model everywhere. The generator and both judges use , so they can share blind spots. Full label agreement is partly a consequence of that.
  • The generator optimizes a measure close to the coverage judge's. High coverage is partly expected by construction. The coverage judge still counts every shape equally and credits only its own verified links.
  • No execution. "Answerable" means every concept links to existing columns and values and the tables connect. It does not prove a query returns a sensible result.
  • Not yet run: the controlled check (edited list with an unanswerable question and a paraphrase), and the robustness runs on different data (TPC-H scale factor 0.01) and a different schema (TPC-DS).

Files
